CRITICAL: NO "FAKE JOINS" (bpmnlint rule: fake-join)
======================================================================
10. NEVER attach multiple <bpmn:incoming> flows directly to an Activity or Task:
    - In BPMN 2.0, connecting multiple sequence flows directly to a task is an invalid pattern called "fake join" or "implicit join".
    - Whenever multiple sequence flows converge (e.g. forward flow + feedback/loopback flow, or alternative decision paths leading to the same step):
      * You MUST ALWAYS route those incoming flows through an intermediate merging Gateway:
        Use <bpmn:exclusiveGateway id="..." name="Merge"> for loopbacks/alternative paths.
        Use <bpmn:parallelGateway id="..." name="Sincronizar"> for parallel branches joining.
      * The merging Gateway receives the converging sequence flows, and emits a SINGLE outgoing sequence flow into the task.
      * Connecting multiple flows directly into a task causes the linter error: "Incoming flows do not join [fake-join]".

CAMUNDA 8 (ZEEBE) EXECUTABLE SPECIFICATION RULES
======================================================================
11. MANDATORY isExecutable="true":
    - The process element MUST have isExecutable="true".

12. SERVICE TASKS (<bpmn:serviceTask>):
    - MUST include a <zeebe:taskDefinition> child inside <bpmn:extensionElements>.
    - The `type` attribute MUST be a meaningful kebab-case identifier (e.g. type="check-inventory", type="charge-credit-card", type="send-email-notification").
    - Always specify retries="3".
    Example:
    ```xml
    <bpmn:serviceTask id="Task_ProcessPayment" name="Procesar Pago con Pasarela">
      <bpmn:extensionElements>
        <zeebe:taskDefinition type="process-payment" retries="3" />
      </bpmn:extensionElements>
      <bpmn:incoming>Flow_1</bpmn:incoming>
      <bpmn:outgoing>Flow_2</bpmn:outgoing>
    </bpmn:serviceTask>
    ```

13. USER TASKS (<bpmn:userTask>):
    - Represents human interaction in Camunda Tasklist.
    - Provide <zeebe:assignmentDefinition> with candidateGroups (e.g. "supervisores", "rrhh", "ventas") or assignee.
    - Provide <zeebe:formDefinition formId="Form_[TaskName]" />.
    Example:
    ```xml
    <bpmn:userTask id="Task_ReviewRequest" name="Revisar Solicitud">
      <bpmn:extensionElements>
        <zeebe:assignmentDefinition candidateGroups="supervisores" />
        <zeebe:formDefinition formId="Form_ReviewRequest" />
      </bpmn:extensionElements>
      <bpmn:incoming>Flow_1</bpmn:incoming>
      <bpmn:outgoing>Flow_2</bpmn:outgoing>
    </bpmn:userTask>
    ```

14. BUSINESS RULE TASKS (<bpmn:businessRuleTask>):
    - Used for automated decision making via DMN tables.
    - Must specify <zeebe:calledDecision decisionId="..." resultVariable="..." />.
    Example:
    ```xml
    <bpmn:businessRuleTask id="Task_CalculateDiscount" name="Calcular Descuento Aplicable">
      <bpmn:extensionElements>
        <zeebe:calledDecision decisionId="Decision_DiscountRules" resultVariable="discountPercentage" />
      </bpmn:extensionElements>
      <bpmn:incoming>Flow_1</bpmn:incoming>
      <bpmn:outgoing>Flow_2</bpmn:outgoing>
    </bpmn:businessRuleTask>
    ```

15. CALL ACTIVITIES (<bpmn:callActivity>):
    - Invokes another independent BPMN process definition.
    - Must specify <zeebe:calledElement processId="..." propagateAllChildVariables="true" />.

16. GATEWAY CONDITIONS & FEEL EXPRESSIONS:
    - Outgoing conditional flows from <bpmn:exclusiveGateway> or <bpmn:inclusiveGateway> MUST use FEEL expressions starting with "= ":
      Example:
      <bpmn:sequenceFlow id="Flow_Approved" name="Aprobado" sourceRef="Gateway_1" targetRef="Task_Next">
        <bpmn:conditionExpression xsi:type="bpmn:tFormalExpression">= aprobado = true</bpmn:conditionExpression>
      </bpmn:sequenceFlow>
      <bpmn:sequenceFlow id="Flow_Rejected" name="Rechazado" sourceRef="Gateway_1" targetRef="End_Rejected">
        <bpmn:conditionExpression xsi:type="bpmn:tFormalExpression">= aprobado = false</bpmn:conditionExpression>
      </bpmn:sequenceFlow>
    - If there is a default fallback branch, mark default="[SequenceFlow_ID]" on the gateway.

17. TIMER EVENTS:
    - Use ISO 8601 duration (e.g. PT1H, P1D, PT15M) or cycle (e.g. R/PT24H) in FEEL formal expression:
      <bpmn:timerEventDefinition id="TimerDef_1">
        <bpmn:timeDuration xsi:type="bpmn:tFormalExpression">PT2H</bpmn:timeDuration>
      </bpmn:timerEventDefinition>

18. MESSAGE EVENTS & CORRELATION:
    - Intermediate catch message events or message start events:
      <bpmn:intermediateCatchEvent id="Event_WaitForApproval" name="Esperar Aprobación">
        <bpmn:incoming>Flow_1</bpmn:incoming>
        <bpmn:outgoing>Flow_2</bpmn:outgoing>
        <bpmn:messageEventDefinition id="MsgDef_1" messageRef="Msg_ApprovalReceived" />
      </bpmn:intermediateCatchEvent>
    - At definitions level (as direct child of <bpmn:definitions>):
      <bpmn:message id="Msg_ApprovalReceived" name="ApprovalReceived">
        <bpmn:extensionElements>
          <zeebe:subscription correlationKey="= orderId" />
        </bpmn:extensionElements>
      </bpmn:message>
